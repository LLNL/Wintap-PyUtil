## Priority gaps for full legacy coverage

### 1. Add DBT source/staging models for enrichment inputs

The current enrichment summaries cannot be made real until these legacy helper/source relations are represented in DBT:

- `labels_networkx`
- `lolbas`
- `lolc_labels`
- `mitre_labels`
- `mitre_car`
- `sigma_labels`
- `sigma`

Recommended approach:

- Add source path variables/macros for optional enrichment and lookup inputs.
- Use typed-empty models when optional files are missing.
- Keep the core build working when no enrichment is present.

### 2. Port graph-label detail/convenience views

Missing DBT models:

- `labels_graph_nodes`
- `labels_graph_links`
- `labels_graph_net_conn`

`labels_graph_process_summary` should then be changed from a stub to a real model depending on `labels_graph_nodes`.

### 3. Replace enrichment summary stubs with real SQL

Existing stubs to replace:

- `labels_graph_process_summary`
- `process_lolbas_summary`
- `process_mitre_summary`
- `sigma_labels_summary`

`process_uber_summary` already joins these models and should work unchanged once they become real populated relations, assuming schemas are preserved.

### 4. Confirm model materializations

Legacy objects mix tables and views. DBT currently materializes all `gold` models as tables by project config, even when legacy objects were views. This is acceptable for current DBT behavior, but should be documented if users expect view semantics.
